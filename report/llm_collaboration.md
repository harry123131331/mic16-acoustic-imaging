# 大模型辅助设计过程

本文件按工程任务归纳大模型辅助设计的输入、建议、修正和验证结果。提示词模板见../skill/prompts.md，排查流程见../skill/workflows.md，典型问题见../skill/failure_cases.md。

## 计算与资源划分

设计任务是识别秒级检测的主要开销，并在有限的逻辑、存储和乘法资源下安排计算。阶段计时表明，特征构建与扫描精算是主要热点；共享运算结构能够减少重复实例，但也会增加资源等待。因此，设计将规则计算映射到共享硬件核，将候选管理、质量判断和控制留在处理器，并按输入搬运、设备计算、结果收取分别核算成本。相关设计摘要见history/astra_architecture_review.md。

修正重点是统一比较范围。完整C16检测与快速主导方向的任务量不同，不能以两者的耗时直接计算加速比。同一个共享设备上的各项服务时间需要相加，不能将它们假定为可同时执行。

## 连续采集与定位解耦

输入每52.4288毫秒形成一个子帧，早期逐帧前端的处理间隔约91.8709毫秒，长计算占用采集槽后会使缓冲耗尽。设计采用20帧PCM环形缓存和最新四帧独立快照，采集帧复制完成即归还DMA槽；定位与原始数据发送分别推进，并记录分析未覆盖区间。

验证检查采样序号、缓存取得与归还、停止排空和重新启动。历史连续测试完成62次定位输出，566帧原始PCM完整接收，数据见../board/baseline_result.json。该结果验证了持续采集和周期更新的调度机制。

## 坐标与显示一致性

设计分别管理阵列坐标和相机投影。阵列球坐标以MIC12方向为方位零点、PCB平面为俯仰零点，正前方法线为90度。旧扫描表的侧向覆盖不足，不能通过修改角度标签补偿，因此重新组织前半球扫描射线，并检查接缝、法线重复与接口绑定。

显示层将方向点、空间响应和采样身份配对；运行序号、采样区间及有效期用于阻止旧结果覆盖当前画面。定位页使用小圆点，视频页保留局部渐变标记。数字模型和协议检查分别验证几何、数值与消息交接，现场记录用于检查实际运行。

## 提炼与验证方法

协作成果以设计规则、排查步骤和验证记录呈现。建议先落实到源码与接口，再以黄金参考、边界检查、离线编译和实板记录逐层核验。技能包中的提示词和脚本适用于类似的DMA流处理工程，并明确所需输入、通过条件和失效情况。
