# 连续逐源音频C参考与M16S接口

新增于既有R7工程；复用冻结C16、原逐源增强器，未替换正式ELF。CPU参考，无设备、堆分配或新跟踪器。当前候选只回放3个完整输入窗，不是直播固件。

## 数据流与边界

`m16_enh_window`对全部本周期确认源生成原掩码／权重 → `m16_cont_push`复制一个40960×16归一化FP32窗及预测 → 保留最多3窗，等待下一窗 → 按全局256/625重采样轴、全局STFT与625原采样点淡入淡出输出各路 → `m16_source_encode`编码 → 同步消费回调。

每周期当前源最多8个；三窗支持区域最多24个不同匿名ID。后者包含淡出／滤波边界音频，绝不能显示成24个当前声源。source_id=0回调为MIC0参考，编码器只在无源时用它发送空窗清单；不把MIC0当声源。

40960点每窗相当于1.048576秒。重建有1窗观察前瞻，不含采集和计算的耗时。4窗应为`ceil(4*40960*256/625)=67109`点，不能拼成`4*16778=67112`点。边界不会重新置零FIR历史。

所有大工作区置DDR/BSS。连续工作区9,387,504字节，含最多3窗PCM、3组预测和复用合成暂存。回调音频是借用数组，必须同步取走。输入中断、序号错误、非有限值、姿态变化或回调失败时放弃当前段；使用新epoch，不补零伪装连续采集。外层负责完整输出窗事务提交；发生中途失败时该窗全部回调作废。C接口不会替调用者验证物理相机／阵列姿态。

## M16S v1线上格式（尚未接UDP发送）

新magic `M16S`与旧MIC16单路ENHANCED_AUDIO帧分开；不修改旧协议、旧端口或旧Qt接收流程。所有多字节字段小端。每包60字节头＋最多128帧×2路float32＝1084字节；两路为该匿名源的WDAS、原神经后处理。float32是归一化音频单位，不能解释为Q31或声压级。

|偏移|类型|字段|
|---|---|---|
|0|4字节|ASCII M16S|
|4|u16|版本1|
|6|u16|bit0本周期确认，bit1最终窗，bit2无源空窗；其他位0|
|8,12,16|u32×3|epoch、窗序号、匿名源ID|
|20,22|u16×2|本窗音频流序号、音频流总数（含边界音频，最多24）|
|24,32|u64×2|全局16kHz起点、终点（左闭右开）|
|40,44,48|u32×3|分片样本偏移、全窗点数、采样率16000|
|52,54|u16×2|本片点数（最多128）、保留0|
|56|u32|CRC32，覆盖前56字节头＋payload，不包含CRC字段本身|
|60|float32×2×点数|按样本交错WDAS、enhanced|

偏移为128的倍数，末片允许不足128。窗口始末必须由窗序号严格推导，不接受自报长度扩大分配。无源清单：source_id=0、流数／序号／分片点数／偏移为0；保留实际时间区间及该窗点数。其他情况下ID为正。

PC接收器位于`../pc_per_source/source_wire.py`。完整检查CRC、版本、有限音频、全局区间、重复ID、源数和分片边界；只在所有源所有分片齐备后返回整窗。容忍窗内乱序和完全相同重复包；冲突、丢片后跨窗或缺最终窗均使段失败。空窗显式传递，不能把未收到网络包当作“没有声源”。接收端最多分配3,221,376字节PCM及有界分片收据；调用者保存返回结果不在此内存上界内。
