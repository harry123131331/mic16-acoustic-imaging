# 流处理工程的证据与数据交接检查

本技能包来自16路采集和定位部署中的具体问题，适用于DMA采集、分阶段计算、网络显示等有持续输入的嵌入式工程。它不依赖声源类别或特定神经网络。

## 使用内容

| 文件 | 用途 | 已验证效果 | 失效条件 |
|---|---|---|---|
| workflows.md | 划分生产者、缓冲、快照和消费者 | 原工程最新窗口方案完成62次输出，566帧RAW完整 | 新任务若必须逐帧分析，不能直接采用跳分析策略 |
| prompts.md | 带输入、约束和验收条件的审查提示词 | 用于整理原工程任务与证据 | 模型建议须再验证，不保证跨工程性能收益 |
| failure_cases.md | 定位槽耗尽、Cache、坐标和版本问题 | 来源与对应观察逐项列出 | 现象相同可能根因不同，应先取证 |
| evidence_audit.py | 样本轴、覆盖和延迟主张检查 | 通过例及三类错误例检查通过 | 不解析硬件中断，不证明实际音频无丢失 |
| examples/valid.json | 可直接运行的通用输入样例 | 纯合同样例，通过审计 | 不是原项目录音或实测成绩 |

## 最短使用步骤

1. 在workflows.md中填写本工程的输入周期、最长阻塞、缓冲所有者和输出要求。
2. 运行python skill/evidence_audit.py --self-test；再按样例字段导出本工程数据，用--input检查。
3. 对照failure_cases.md查证具体计数和时间口径；需要模型协助时复制prompts.md并填写已有数据。
4. 保存结果和未确认项。跨设备时重新检查Cache行大小、DMA协议、时钟域和STOP语义。

本工程使用裸机与Qt，未提供或申报PYNQ专用封装。验证效果来自本工程，跨题目适用范围尚需使用者验证。
